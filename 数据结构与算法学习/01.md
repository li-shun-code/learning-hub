# 01 · 复杂度分析：不跑代码，怎么知道它快不快？

> 前置知识：能读懂简单的 Python 循环与函数；知道高中等比数列即可。
> 难度：入门
> 预计阅读时间：20 分钟

## 正文内容

### 一、先别急着学方法，先想清楚一个问题

假设你写了两段代码，都能算 1 到 n 的累加和。你想知道哪段更快，最直接的办法是什么？

**先自己想 10 秒**，再往下看。

……

多数人的答案是：跑一下，计时。

这叫**事后统计法**，它是对的，但有两处硬伤：

1. **依赖环境**。同一段代码在不同 CPU 上跑，时间差好几倍；甚至 A 代码在这台机器上比 B 快，换台机器就反过来。
2. **依赖数据**。同一个排序算法，数据是"已经排好序"还是"完全乱序"，耗时天差地别。数据规模太小时，插入排序甚至可能比快排还快。

所以我们需要一种**不依赖具体机器、不依赖具体测试数据**的估算方法。这就是复杂度分析。它的重要性怎么强调都不过分：**复杂度分析是整个算法学习的精髓，掌握它，数据结构与算法就掌握了一半。**

> 类比：事后统计像是"这次考试考了多少分"，复杂度分析像是"这个学生的学习能力增长率"。前者受试卷难度影响，后者才是真正可比较的东西。

### 二、大 O：数的是"执行次数"，看的是"增长趋势"

推导很朴素：假设每一行代码在 CPU 上执行的时间都一样，叫 `unit_time`。那么**总执行时间 T(n) 和每行代码的执行次数成正比**。

看第一段代码：

```python
def cal(n):
    total = 0          # 1 次
    i = 1              # 1 次
    while i <= n:
        total += i     # n 次
        i += 1         # n 次
    return total
```

把次数加起来大约是 `2n + 3` 次，所以 `T(n) = (2n+3) * unit_time`。

再看嵌套的版本：

```python
def cal2(n):
    total = 0
    i = 1
    while i <= n:          # n 次
        j = 1
        while j <= n:      # n * n 次
            total += i * j
            j += 1
        i += 1
    return total
```

这次是 `T(n) = (2n² + 2n + 3) * unit_time`。

**关键一步来了**：当 n 大到 10000、100000 时，`2n²` 里的 2、`+2n`、`+3` 都不影响增长趋势。大 O 表示法只保留最大量级：

- `T(n) = O(n)`
- `T(n) = O(n²)`

> **大 O 不是代码真正跑了多久，而是执行时间随数据规模增长的变化趋势**（渐进时间复杂度）。

这里最容易踩的坑：有同学看到 `O(1)` 以为"只执行了 1 行"。不是的——`O(1)` 表示**执行时间不随 n 增长**。哪怕你写 1000 行顺序执行的代码，只要没有循环和递归，它还是 `O(1)`。

### 三、三个够用的分析技巧

**不要背公式，而是每次按这个顺序问自己**：

**技巧 1：只盯循环执行次数最多的那段。**
常量级的语句（`total = 0`、`return`）跟 n 无关，直接忽略。找到嵌套最深、跑得最多的那几行，它的次数就是答案。

**技巧 2：加法法则——并排的多段代码，取量级最大的。**

```python
def cal3(n):
    a = sum(range(100))            # O(1)：100 是常数
    b = sum(range(n))              # O(n)
    c = 0
    for i in range(n):
        for j in range(n):
            c += i * j             # O(n²)
    return a + b + c
```

三段并排，总复杂度 = `max(O(1), O(n), O(n²))` = **O(n²)**。

注意这里反直觉的一点：哪怕第一段循环 1 万次，只要次数和 n 无关，它就是 O(1)。复杂度看的是**趋势**，不是绝对耗时。

**技巧 3：乘法法则——嵌套的代码，复杂度相乘。**

```python
def f(n):
    return sum(range(n))           # O(n)

def cal4(n):
    total = 0
    for i in range(n):             # 外层 O(n)
        total += f(n)              # 内层调用 f，也是 O(n)
    return total
```

`O(n) * O(n) = O(n²)`。你可以把"调用函数"直接看成把那几行代码展开在这里。

### 四、常见量级：其实就这五个

| 复杂度 | 长什么样 | 典型例子 |
|---|---|---|
| O(1) | 没有循环 / 递归 | 数组按下标取值 |
| O(logn) | 每轮规模减半（或乘 2 逼近） | 二分查找 |
| O(n) | 单循环 | 求累加和 |
| O(nlogn) | O(logn) 的操作做 n 遍 | 归并排序、快排 |
| O(n²) | 双重循环 | 冒泡排序 |

`O(logn)` 最容易卡住，换个角度感受一下：

```python
i = 1
while i <= n:
    i = i * 2
```

`i` 的取值是 1, 2, 4, 8, 16… 也就是 `2⁰, 2¹, 2², 2³…`。循环 x 次后 `i = 2ˣ`，当 `2ˣ > n` 时结束，所以 `x ≈ log₂n`。

**为什么底数可以省略？** 因为 `log₃n = log₃2 × log₂n`，前面那个 `log₃2` 是常数，大 O 忽略常数，所以统统写成 `O(logn)`。

> 还有两类**非多项式**量级：`O(2ⁿ)` 和 `O(n!)`。它们对应的问题叫 NP 问题，数据一大就爆炸，初学者遇到就知道"这类问题没法要高效解"即可。

### 五、空间复杂度：同一套思路，换成"内存"

时间复杂度看执行次数随 n 怎么涨，空间复杂度看**申请的内存随 n 怎么涨**，分析方法完全一样。

```python
def print_squares(n):
    i = 0                    # 1 个变量，O(1)
    arr = [0] * n            # n 个空间，O(n)
    for k in range(n):
        arr[k] = k * k
    return arr
```

除了那个长度为 n 的数组，其他都是常量级，所以空间复杂度是 **O(n)**。

常见的空间复杂度只有 `O(1)`、`O(n)`、`O(n²)` 三种，`O(logn)` 那种几乎用不到。

### 六、这一篇你真正要带走的东西

1. 复杂度分析不是"跑一遍计时"，而是**看增长趋势**——所以能脱离机器和数据规模做比较。
2. 大 O 的实操口诀：**忽略常数、低阶、系数，只留最大量级**。
3. 分析顺序：**盯最内层循环 → 多段取最大 → 嵌套相乘**。
4. 看到 `while i <= n: i *= 2` 就想到 `O(logn)`；看到双重循环就想到 `O(n²)`。

后面学每一种数据结构（数组、链表、散列表、二叉树……）时，都会分析它的时间 / 空间复杂度。那时你就把这篇的口诀拿出来用，**每分析一次就熟练一分**。
