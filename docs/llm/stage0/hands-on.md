# 4. 实战：AI 辅助写小工具

这一节我们完整走一遍「描述需求 → 生成 → 审查 → 修改 → 交付」的循环。目标是做一个实用的小工具：**批量统计一个文件夹里各类文件的数量和总大小**。

## 任务描述

先用文字把需求写清楚（这一步不要跳过，它训练你把模糊想法变成清晰指令）：

```text
请写一个 Python 脚本 file_stats.py：
- 接收一个文件夹路径作为命令行参数
- 递归统计该文件夹下每种扩展名（如 .py、.txt、.md）的文件数量和总大小（字节）
- 按文件数量从多到少排序，在终端打印成表格
- 对无读取权限的文件跳过，不中断程序
- 使用标准库，不装第三方依赖
写完后：
1. 逐段解释代码
2. 给出运行示例
3. 指出这段代码可能的两个不足
```

## 第一步：让 AI 生成初稿

把上面的指令贴给你选的工具，拿到初稿。别急着复制运行，先看结构：

- 是否用了 `argparse` 处理命令行参数？
- 是否用了 `pathlib` 或 `os.walk` 递归遍历？
- 是否用字典按扩展名累计数量和大小？
- 是否有异常处理（跳过无权限文件）？

## 第二步：审查并运行

把代码保存到测试文件夹，运行：

```bash
python file_stats.py E:\code\test-ai
```

::: warning 常见问题
- 报错 `ModuleNotFoundError`：说明用了第三方库但你没装——回到约束「只用标准库」让 AI 重写。
- 输出乱码：Windows 终端编码问题，可让 AI 加上 `sys.stdout.reconfigure(encoding='utf-8')`。
- 统计结果不对：自己造几个已知数量的文件验证，别只信 AI 说「测试通过」。
:::

## 第三步：让它自己挑毛病并修改

把生成的代码贴回去，追加一句：

```text
现在请你以代码审查者的身份，指出这段代码在健壮性、可读性、性能上的三个问题，并给出修改后的完整代码。
```

这一步的价值很高：**你不是在让 AI 干活，而是在借它训练自己的审查能力**。把指出的每个问题和你的理解对一对，不懂就追问。

## 第四步：自己动手改一处

选一个你理解的改进点自己改，例如：

- 把大小从「字节」改成人类可读的 KB / MB；
- 加一个参数 `--top` 只显示前 N 种扩展名；
- 加上对隐藏文件的过滤。

改完再运行一次，确认输出符合预期。**能自己改，才算真的懂了**。

## 交付标准

完成后你应该有：

- [x] 一个能运行的 `file_stats.py`
- [x] 一段你写的 README，说明这个工具做什么、怎么运行
- [x] 能说清代码里每一部分的作用

## 小结

这四步——**描述需求 → 生成 → 审查 → 修改**——就是后面整个学习过程你会反复用的节奏。工具会换、模型会升级，但这个循环不会变。
