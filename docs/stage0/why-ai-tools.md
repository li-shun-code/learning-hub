# 1. 为什么先学 AI 工具

## 一个现实的变化

几年前学编程，路径是「买本书 → 装环境 → 从头敲到尾 → 遇到问题搜搜索引擎」。现在不是了。现在的高效路径是：

> 描述需求 → AI 生成初稿 → 你审查和修改 → 遇到问题让 AI 解释 → 在实践中理解原理

这不是「偷懒」，而是把学习重心从「记住语法」转移到「理解问题、判断方案、审查结果」——这些才是 AI 时代更值钱的能力。

## AI 工具能帮你做什么

| 场景 | 传统方式 | 用 AI 工具 |
|---|---|---|
| 写一个小脚本 | 翻文档、查 API、逐个敲 | 描述需求，几分钟拿到初稿 |
| 看懂一段陌生代码 | 一行行搜、猜 | 让 AI 逐段解释，再自己验证 |
| 报错排查 | 复制报错到搜索引擎翻帖子 | 把报错和上下文贴给 AI，让它分析 |
| 写测试、写文档 | 手工补，容易忘 | 让 AI 生成，自己审查补充 |
| 学新框架 | 通读官方文档 | 让 AI 用你已经懂的东西类比着讲 |

## 三个必须建立的认知

::: warning 认知一：AI 会「一本正经地胡说」
AI 生成的代码看起来很专业，但可能调用不存在的 API、用错参数、有安全隐患。**任何 AI 输出都要你自己跑一遍、看懂一遍**。
:::

::: warning 认知二：答案质量取决于你的指令
「帮我写个爬虫」得到的东西基本没法用；「用 Python 的 requests 和 BeautifulSoup 写一个爬取某网站标题的脚本，只取 h1 标签，加上异常处理和超时设置」才能得到可用代码。**指令越具体，结果越可用**。
:::

::: warning 认知三：上下文是有容量和成本的
你给 AI 的信息越多（对话历史、贴的代码、文件），它处理的「上下文」越长，反应越慢、成本越高，而且注意力会分散。**学会管理上下文，是进阶的关键**。
:::

## 常见误区

- **误区 1：完全依赖 AI，不看它写的代码。** 后果：你永远学不会，而且线上出事故你修不了。
- **误区 2：觉得 AI 无所不能，不做验证。** 后果：调用了不存在的库、用错版本，浪费大量时间。
- **误区 3：把工具当搜索引擎用，问完就走。** 后果：每次都从零开始，没有积累可复用的 Prompt 和项目上下文。

## 这一阶段的目标定位

你不需要成为 AI 工具专家，只需要达到：

1. 能流畅地用一款工具完成「写代码 → 跑代码 → 改代码」的循环；
2. 知道怎么提问、怎么给上下文、怎么审查结果；
3. 后面学 Python 和做项目时，能自然地把 AI 当作副驾。
